# 03｜预测、估值与预期差建模规范

本文件定义当研究任务涉及盈利预测、情景分析、估值、市场预期/Price-in 或“值不值得买”等一阶投资判断时，如何把已经核验的证据稳定地转换为 Forward Earnings、合理估值区间和条件式 Research-to-Action。

本文件不替代 Reference 01 的证据裁决，也不替代 Reference 02 的完整研究框架；它只约束从“已知事实”到“未来盈利与估值”的建模过程，降低无依据的假设漂移、估值方法漂移和跨 Run 结论漂移。

## 1. 建模边界：先事实，后假设，再估值

必须按以下顺序工作：

> Actual / 已核验事实 → 可验证的管理层指引与市场预期 → 关键经营假设 → Earnings Bridge → Base/Bull/Bear → Valuation → Price-in → Risk/Reward → Research-to-Action

禁止：
- 先有目标价，再反推盈利或倍数；
- 把传闻订单、远期产品、未确认客户直接写进 Base Actual；
- 把 Management Guidance、Verified Consensus、Single Analyst Forecast、Model Estimate 混成一个数字；
- 因为某个估值口径看起来便宜，就选择该口径作为最终答案；
- 为了提高跨 Run 稳定性而写死公司、行业、增长率、利润率或估值倍数。

## 2. 研究时间截面与输入台账

涉及 Forward / Valuation 时，先固定同一研究截面：
- Price cutoff
- Financial cutoff
- Consensus / analyst-sample cutoff
- Industry / commodity / key operating-data cutoff
- News / company-update cutoff

不得静默混用明显不同时间截面的价格、财务、盈利预测与行业数据。

对所有进入模型的关键输入，至少区分：
1. **Actual**：已披露并可核验的历史事实；
2. **Management Guidance**：管理层明确给出的未来指引或目标；
3. **Verified Consensus / Institutional Sample**：符合 Reference 01 定义的市场预期；
4. **Evidence-supported Operating Assumption**：由订单、客户、产能、价格、行业数据等支持的经营假设；
5. **Model Assumption**：研究者为完成建模引入、但没有被外部事实直接确认的假设。

同一输入不得在不同段落中无说明地改变身份。

## 3. Forecast Anchor：先建立基准，再做上修或下修

盈利预测必须先建立可解释的 Forecast Anchor，而不是从最终净利润倒推。

优先使用：
- 最新完整年度 + 最新季度/半年度 Actual；
- 可验证的当前 run-rate；
- 公司正式 Guidance（如有）；
- 可靠 Verified Consensus / Institutional Sample 作为外部基准；
- 已确认产能、交付、价格、销量、客户和产品结构变化。

如自建 Base 与可靠 Consensus 存在显著差异，必须说明：
- 差异来自哪一个经营变量；
- 为什么市场预期可能高估或低估；
- 支持该差异的证据；
- 哪个新数据会使自建预测向 Consensus 回归。

不得因为“希望更保守”或“希望更积极”而在没有经营桥接的情况下直接给预测打折或加成。

## 4. Earnings Bridge：预测必须能从经营变量走到利润与现金流

对决定估值的未来1—3年，按企业适用性建立可审计的 Earnings Bridge。

### 4.1 收入桥
优先拆成适用的核心变量：
- Volume / shipment / users / capacity utilization
- ASP / price
- Product / customer / regional mix
- Market share
- New capacity / new product / new customer
- M&A / consolidation / one-off items

若无法可靠量化，明确标为 Partial / Model Assumption，不得伪造精确值。

### 4.2 利润桥
至少检查：
- Gross margin：价格、产品结构、良率、原材料、折旧、规模效应；
- Operating expenses：研发、销售、管理、SBC等适用项目；
- Interest / tax / minority interests / non-recurring items；
- Share count / dilution，若会实质影响 EPS 或每股估值。

### 4.3 现金流桥
当现金流是投资判断的重要约束时，至少检查：
- Accounts receivable
- Inventory
- Contract liabilities / deferred revenue
- Capex / construction in progress
- Working capital
- OCF / FCF conversion

利润预测与现金流明显背离时，必须说明原因；不能只完成利润表建模后忽略现金兑现。

## 5. Base / Bull / Bear 的构造纪律

### Base
Base 不是三个情景的机械中点，也不是为了保守而随意打折；应代表在当前证据、管理层指引、行业数据和合理经营假设下，**最能被证据支持的中央情景**。

### Bull
只上修真正可能改变结果的关键驱动，例如需求、份额、价格、产品结构、产能利用率、利润率或商业化时点；不得把所有变量同时调到最好。

### Bear
必须包含最有可能破坏主逻辑的变量，而不是为了形成对称区间机械减数；需与 Reference 01 的反证和推翻条件相连接。

三种情景必须共享同一：
- 研究时间截面；
- 历史 Actual；
- 股本/币种/单位口径；
- 会计口径；
- 已确认事实。

情景之间只能改变明确列出的 Forward Assumption。

概率只有在有可解释依据时使用；否则不提供伪精确加权目标价。

## 6. 周期行业：Normalized Earnings 必须显式建模

资源、航运、化工、存储、面板等强周期公司，不得用当前高景气利润 × 低 PE 直接认定低估。

正常化盈利至少拆出适用变量：
- 中周期价格/运价/价差；
- 可持续销量/产量；
- 成本曲线；
- 汇率；
- 税费/特许权使用费；
- 维持性资本开支；
- 库存与可售量；
- 资产寿命或新增产能。

明确区分：
- Spot / current-cycle earnings
- Normalized / mid-cycle earnings
- Structural new earnings base

若认为本轮周期已发生结构性抬升，必须给出能证明“旧中枢失效”的证据，而不能只因近期价格高就永久上修正常化利润。

同一 Base 情景下，不得同时使用“高景气利润”与“中周期低倍数”进行 valuation shopping。

## 7. 估值方法选择：先匹配经济特征，再交叉验证

估值方法按企业经济特征选择：
- 稳定、可预测现金流：DCF + PE/EV/FCF yield 交叉验证；
- 成熟盈利公司：Forward PE / EV-EBITDA / FCF 等；
- 高增长但已盈利：Forward earnings + 增长、利润率、现金流质量与可比公司交叉；
- 金融：PB / ROE / 盈利质量等适用框架；
- 强周期：Normalized Earnings + PB / EV / NAV 等适用交叉；
- 亏损成长：PS / EV-Sales + unit economics / path-to-profitability；
- 多业务集团：SOTP；
- 现金流不可预测时，不用精确 DCF 制造虚假确定性。

可偏离，但必须解释为什么。

至少使用一个主估值方法；当另一个方法能有效暴露主方法盲点时再做交叉验证。禁止为了“看起来完整”机械使用全部方法。

## 8. Multiple / Discount Rate 的选择纪律

任何关键倍数、WACC、永续增长率或终值假设，都必须有可解释锚点。可使用：
- 公司自身历史估值区间（注意业务阶段变化）；
- 真正可比公司的估值；
- 增长、ROIC/ROE、利润率、现金流质量；
- 周期位置；
- 客户集中、技术、监管、资本强度等风险；
- 市场利率和资本成本环境。

不得：
- 仅因“行业一般给20倍”直接套用；
- 仅选择最有利同行；
- 同时给更高盈利和更高倍数，却不说明为什么双重上修合理；
- 用远期高增长倍数给已经明显降速的盈利阶段。

若不同合理倍数会改变投资结论，必须展示敏感性，而不是隐藏选择风险。

## 9. Consensus 与 Own Model 的双轨制

可靠市场预期存在时，同时保留两条轨：

### Market Track
回答市场目前在预期什么：
- Verified Consensus / Institutional Sample
- 盈利修正方向
- 管理层 Guidance
- 已知催化与市场叙事

### Research Track
回答基于证据的自建模型认为会发生什么：
- Base / Bull / Bear
- 与市场预期的差异
- 差异的经营原因
- 何时可被验证

不得把 Own Model 写成 Consensus，也不得因为存在 Consensus 就停止独立建模。

## 10. Price-in：必须做反向检查

涉及“贵不贵、值不值得买、还有多少空间”时，不只计算“模型值多少钱”，还要反向回答：

> 当前价格大致要求未来实现什么收入、利润、现金流、ROE、商品价格或估值倍数？

再比较：
- 当前证据能否支持市场隐含要求；
- 市场要求的是已确认事实，还是仍需兑现的假设；
- 哪个变量一旦低于市场要求，会触发估值压缩；
- 哪个变量超预期，才构成真正的预期差。

Price-in 分析优先关注一阶驱动，不为精确感反推出过多不可验证参数。

## 11. 估值时间点与每股口径

任何目标价值或估值区间必须说明：
- 使用哪一年的盈利/现金流；
- 估值对应“当前研究时点”还是“未来某一时点”；
- 若是未来价值，是否需要折现回当前；
- 使用的总股本 / diluted shares；
- 币种与单位；
- A/H、ADR、双重上市等是否使用了正确 Security 的价格与股本口径。

禁止把未来终值直接与当前价格比较而不说明时间差。

## 12. 稳定性与可解释漂移

同一截止时间、相同核心证据的重复运行，预测和估值允许因合理不确定性出现差异，但差异必须能够追溯到明确的关键假设。

若 Base Earnings、Normalized Earnings、关键 Multiple 或合理价值区间发生足以改变投资动作的明显变化，必须指出：
- 哪个输入或假设发生了变化；
- 为什么变化；
- 新证据是什么；
- 若没有新证据，为什么旧假设需要重估。

没有新证据时，不得静默大幅改变中央情景。

稳定的目标是**方法、口径和因果桥稳定**，不是固定答案。

## 13. Research-to-Action 接口

最终行动判断必须由以下四项共同决定：
1. Business / financial quality
2. Earnings realization / forecast confidence
3. Valuation / Price-in
4. Downside / invalidation risk

公司质量高不能自动推出“现在值得买”；估值低也不能在盈利质量或周期位置恶化时自动推出“低估”。

当 Base、Bull、Bear 跨越明显不同结论时，优先输出条件式判断和触发条件，而不是伪造单一确定目标价。

## 14. 最小充分输出

本文件是内部建模规范，不要求前台机械输出完整模型。

简单问题可压缩，但后台至少应完成：
- Forecast Anchor
- Base关键假设
- 主估值方法
- Price-in / 反向检查
- 关键敏感性与失效条件

完整深研按 Reference 02 组织输出；只有当数字会影响一阶结论时，才展开详细预测表、估值表和敏感性表。
